Packages (alpm)

alpm

Arctic's package manager, written specifically for this distribution. Binary packages are .alpmz files - a plain tar.xz archive holding a .PKGINFO metadata block, a .FILES manifest, and the payload rooted at /.

alpm add vim              install
alpm rem vim              remove
alpm rem -d vim         remove, and anything only it needed as a dependency
alpm search editor        search names and descriptions
alpm info vim             what a package is, its version, its dependencies
alpm list                 everything currently installed
alpm files vim            every file a package owns
alpm owns /usr/bin/vim    which installed package owns a given file
alpm fetch all            refresh the repository indexes over the network
alpm upgrade              upgrade everything installed to the latest available
alpm system get           the installed release, kernel and generation
alpm system check         everything system upgrade would do - nothing applied
alpm system upgrade       sync, upgrade packages and the kernel, apply pending
                          fixes, reconcile the declarative config files

Every add/rem updates pkgs.conf's mirror automatically - see configuration. There's no separate declarative package list to keep in sync; plain alpm add is the normal, correct way to manage packages.

alpm system get / check / upgrade

Some corrections don't move a package version: a default that turned out to be harmful, a service file that was wrong, a script that failed on some machines. An upgrade can't carry those, since there's no newer version to upgrade to. The fix repository is where they live - an ordinary binary repository, so applying a fix is still an install and the system stays binary, with one extra file naming which correction rides in which package.

alpm system check bootloader    only what might explain a machine that will not boot
alpm system upgrade kernel
alpm system upgrade major       only the most serious fixes
alpm system upgrade bugfix      both fix levels, and none of the plain changes

Every pending fix is listed before anything installs, and applied fixes are remembered, so one is offered once and never again. alpm system upgrade runs arctic-rebuild itself at the end, so a package upgrade and a config change converge through one command.

Building from source

Not every package has a binary built for it. When one doesn't, alpm offers to build it on the spot.

alpm add -s some-package    build from the port, even when a binary also exists
alpm build recipe           build a specific recipe file into an .alpmz directly

Recipes come from the ports tree, a separate host from the binary mirror, reached through ALPM_PORTS - never one of the repositories in /etc/alpm/repos.d.

Undoing a transaction

alpm rollback              undo the most recent transaction
alpm rollback 20260815-111525    undo a specific one
alpm log                   what has been done, and which transactions are on disk

On a btrfs root alpm also takes a filesystem snapshot before every transaction, catching anything a package's install script did on its own - separate from file-level rollback.

Reporting style

ALPM_STYLE in /etc/alpm/alpm.conf chooses the wording and layout. The resolver, downloads and progress are identical in all three.

arcticthe default - :: headings, a line per dependency
aptDebian's shape
aerynAeryn OS's shape - a boxed, columnar transaction summary

Repositories

mainthe base system and the libraries it needs
basedesktops, X11, Wayland, and other larger stacks
extraapplications and general-purpose tools
kernelskernels, kernel headers, firmware
profilewhole-environment meta packages - a desktop, an audio stack, in one name
fixcorrections that no version change would carry
bigpackages past the mirror's file size limit: firmware, the toolchain
nonfree, alt-nonfree, multiliboff by default; opt in explicitly

Configured per repository in /etc/alpm/repos.d/*.repo:

name = main
url = https://raw.githubusercontent.com/apiwo/arctic-linux-pkgs/main/ALL/main
enabled = yes
priority = 10
sig = optional

Browse contents at arctic-linux-pkgs and recipes at ports-arctic.apiwow.net.

Signatures

Every index is signed with signify - Ed25519, one line of public key, no GPG anywhere near the base system. The public key arrives with arctic-base, in /etc/alpm/keys, before the first fetch.

sig = required   an index without a good signature is not used
sig = optional   checked when it can be, said out loud when it cannot (default)
sig = off        not checked at all

Ephemeral shells

arctic-shell git tmux ripgrep       a throwaway environment with those packages
arctic-shell --network curl         with network access
arctic-shell --keep vim -- vim x    build it, keep it after you exit
arctic gc                           clean up the package cache and unused environments

Content-addressed by package set, so the same request reuses a previous build instead of rebuilding it. Every invocation also sweeps for an environment left mounted by a session that was killed outright - unmounted, and removed unless it was built --keep.

Ports

Every package in the repositories is generated from a single line in ports/manifest.tsv:

repo  name  version  buildsys  license  depends  makedepends  url  source  desc

gen-ports.py turns each row into a recipe matched to the declared build system. A package that needs something the template can't express gets a hand-written recipe with a recipe.local marker beside it, which stops the next manifest-driven regeneration from overwriting the hand work.

Package and recipe changes go to arctic-linux-ports, not the main arctic-linux repository.
