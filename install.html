Install

No ISO, no guided installer. Boot any live Linux with tar, curl or wget, and disk tools - Arctic's own media is not needed for this step. The short version is on the main page; this covers the parts that guide leaves out.

Partitioning

By hand, with fdisk/sfdisk/cfdisk or whatever the live environment gives you. What you need depends on firmware and bootloader:

LayoutPartitions
UEFI + LimineEFI System Partition (FAT32, ~512M) + root
BIOS + Liminea small unformatted boot-stub partition (~1M, type 21686148-6449-6E6F-744E-656564454649) + a FAT32 /boot (~512M, Limine's BIOS build has no ext4 reader) + root
BIOS + GRUBa small unformatted BIOS boot partition (~1M, type 21686148-6449-6E6F-744E-656564454649) + root - GPT disks need one, GRUB refuses to embed in a bare gap
mkfs.ext4 /dev/sdX2
mount /dev/sdX2 /mnt
mkfs.fat -F32 /dev/sdX1
mount --mkdir /dev/sdX1 /mnt/boot

Root can be ext4, ext3, ext2, btrfs, xfs or f2fs - whatever the live environment's mkfs.* tools support. For an encrypted root, run cryptsetup luksFormat and cryptsetup open before formatting, and write /etc/crypttab by hand once chrooted in (a single cryptroot UUID=<luks-uuid> none luks line) - arctic-mkinitramfs reads it back to decide whether to bundle cryptsetup into the initramfs.

Extracting the tarball

tar -xJf arctic-linux-def-tarball.tar.xz -C /mnt

Two flavors: def (busybox init, the tested default) and openrc (OpenRC already wired up as init instead). Both bundle glibc, toybox, busybox, zsh, doas, e2fsprogs, and alpm itself, pre-installed and ready to sync. Neither bundles arctic-base, a kernel, or a bootloader - those come from alpm add once repo indexes are synced.

Bootstrapping alpm

/mnt/usr/bin/alpm-strap /mnt

alpm-strap's only job is syncing fresh repository indexes into the extracted tree. It passes ALPM_CONF/ALPM_REPOD explicitly rather than relying on their defaults, because those default to host-absolute paths - correct when a live Arctic session with real /etc/alpm config is doing the installing, wrong here, since whatever booted this could be any live Linux with no /etc/alpm at all.

fstab, before chroot

ALPM_ROOT=/mnt ALPM_CONF=/mnt/etc/alpm/alpm.conf ALPM_REPOD=/mnt/etc/alpm/repos.d \
  /mnt/usr/bin/alpm add genfstab
/mnt/usr/bin/genfstab /mnt >> /mnt/etc/fstab

genfstab reads /proc/mounts from the live environment's own view - it has to run before chroot, not after, since a chroot has no view of the outer mount table without /proc bind-mounted first. It writes UUID=, never PARTUUID=: the initramfs resolves root= with busybox findfs, which only understands LABEL=/UUID=.

Inside chroot

/mnt/usr/bin/arctic-chroot /mnt

Bind-mounts /proc /sys /dev /run and drops you into a shell with a correct backspace (stty erase ^? is set explicitly, since the target has no terminfo database yet to agree with the terminal on what backspace even sends).

passwd
adduser you
alpm add arctic-base
alpm add arctic-base-kernel
alpm add limine
arctic-mkinitramfs

Swap limine for grub on a BIOS install if you'd rather have GRUB. Swap arctic-base-kernel for any other flavor - alpm search kernel lists them, see kernels. arctic-mkinitramfs only needs to run explicitly here because you're doing it from inside a chroot rather than through a normal package upgrade, which triggers it as a hook automatically afterward.

Exit the chroot when done (exit or Ctrl-D).

Finishing and the bootloader

Back on the live environment, as root:

arctic-rebuild

This activates any kernel package still marked -nomod (a kernel installed from inside a chroot can't run its own post-install hooks there - no running kernel to build an initramfs against yet) and writes limine.conf/grub.cfg from the real /etc/fstab//etc/crypttab now sitting on the target. It never runs the actual deploy command - that's the one manual step left:

# BIOS, Limine
limine bios-install /dev/sdX

# EFI, Limine - copy the binaries onto the mounted ESP, then register an entry
mkdir -p /mnt/boot/EFI/BOOT /mnt/boot/EFI/arctic
cp /usr/share/limine/BOOTX64.EFI /mnt/boot/EFI/BOOT/
cp /usr/share/limine/BOOTX64.EFI /mnt/boot/EFI/arctic/arcticx64.efi
efibootmgr --create --disk /dev/sdX --part 1 \
  --loader '\EFI\arctic\arcticx64.efi' --label 'Arctic linux'

# BIOS, GRUB
grub-install --target=i386-pc --boot-directory=/mnt/boot /dev/sdX

Reboot.

Repairing an existing install

Mount the root partition (and boot partition, if separate) under /mnt, then /mnt/usr/bin/arctic-chroot /mnt - the same tool used during install works identically afterward. Re-run arctic-rebuild from outside the chroot to fix a stale bootloader config or reactivate a kernel.
