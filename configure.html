Declarative config

Arctic stays declarative after install too — the same relationship NixOS's configuration.nix has to nixos-rebuild switch, built on top of alpm rather than replacing it.

system.conf + arctic-rebuild

/etc/arctic/system.conf lists every package and service that should exist — not a list of things to add, the actual list. Add a name and rebuild installs it; delete a name and rebuild removes it (and anything that was only pulled in as its dependency).

vi /etc/arctic/system.conf
arctic-rebuild

First run, if the file is empty: nothing gets removed. It seeds SYS_PACKAGES/SYS_SERVICES from whatever is already installed and enabled, so you always start from a known-accurate snapshot instead of an empty list that would delete everything.

SYS_PACKAGES="
	git
	tmux
	ripgrep
"

SYS_SERVICES="
	dbus
	network
	sshd
"

Every rebuild snapshots first if the root filesystem is btrfs (the same mechanism alpm itself already uses before any install or removal), so a rebuild that goes wrong is never a one-way trip.

Rolling back

arctic generations   # list snapshots
arctic rollback <name>

Cleaning up

arctic gc prunes orphaned packages, old cached .alpmz files, old snapshots beyond the retention count, and any arctic-shell environment that hasn't been touched in a week and wasn't built with --keep.

arctic gc
