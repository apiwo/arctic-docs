musl

Arctic is fundamentally a glibc distribution. musl exists as an additional, opt-in library installed alongside glibc at /usr/musl — not a separate system, not a replacement. A full musl-based edition (everything rebuilt against musl, the way Alpine is) is a much bigger undertaking than this is yet.

What exists today

  • musl — the library itself, plus the musl-gcc wrapper for building things against it.
  • A dedicated musl repo for packages built against it (see the package mirror). Names get a -musl suffix when a glibc package of the same name already exists — busybox-musl alongside the regular busybox — since alpm's local database is keyed by name regardless of repo.

Trying to install a binary package on a musl root

Arctic's binary repo is always built against glibc, regardless of which root alpm is pointed at. Installing one of those binaries onto a musl root would fail at runtime with an unresolvable dynamic linker, so alpm checks for this and falls back to building from source instead, with a heads-up first.

Building something against musl yourself

alpm ins musl
CC=/usr/musl/bin/musl-gcc <your build command>

Two things musl packages here tend to need that glibc ones don't:

  • Pass CC= on the actual build command line, not just as an exported shell variable — a lot of Makefiles assign CC = gcc themselves, which wins over a plain export.
  • musl folds crypt()/libm/librt straight into its libc — there's no separate static lib for any of them, so a build that unconditionally tries -lcrypt -lm -lrt under -static can fail outright. Dynamic linking against musl's own libc.so doesn't hit this.
